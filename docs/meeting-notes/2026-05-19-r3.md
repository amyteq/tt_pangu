## 2. Supabase local DB verification

**Q (Chinese):**
> Supabase 本地容器已经启动, 请使用 postgres/s3cr3t 连接并验证 DB schema 更改

**Q (English):**
> The local Supabase container is running. Connect using postgres/s3cr3t and
> verify the DB schema changes.

**Connection problem encountered:**

The user initially provided `SUPABASE_DB_URL=postgresql://postgres:s3cr3t@localhost:5432/postgres`.
Port 5432 on `localhost` is served by the **Supabase Supavisor pooler**, which requires
a tenant header (`?options=reference=<project-ref>`). Connecting without it returns:
`"Tenant or user not found"`.

**Solution:**
Connect via Docker container IP directly to Postgres (bypassing Supavisor):
```bash
docker inspect supabase-db --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
# → 172.21.0.4

SUPABASE_DB_URL=postgresql://postgres:s3cr3t@172.21.0.4:5432/postgres?sslmode=disable
```

Prior migrations 0001+0002 had not been applied. Applied all three in sequence:
```bash
docker exec -i supabase-db psql -U postgres -d postgres < supabase/migrations/0001_init.sql
docker exec -i supabase-db psql -U postgres -d postgres < supabase/migrations/0002_kca_run_alignment.sql
docker exec -i supabase-db psql -U postgres -d postgres < supabase/migrations/0003_m3_worker.sql
```

All three applied cleanly. Schema verified: `agent_job_events` table exists, `agent_jobs`
has `workspace_path`, `turns_used`, `cost_usd`, `policy` columns. 17/17 tests pass with live DB.

**Recorded in:** `docs/tooling/local-supabase.md`, `docs/tooling/env-configuration.md`

## 3. Empty files generated during M3

**Q (Chinese):**
> 本次 milestone (M3) 任务为何生成了很多空文件, 如 .bashrc, .bash_profile, .gitconfig 等等,
> 这些文件是预留做什么用的? 如果这些空文件没用的话，请删除，否则保留，并 commit/push 这次的修改

**Q (English):**
> Why did the M3 milestone generate many empty files such as .bashrc, .bash_profile,
> .gitconfig, etc.? What were they reserved for? If they're useless, please delete them;
> otherwise keep them and commit/push.

**A:**
The empty files were created by a `git worktree add --detach` operation during the
workspace lifecycle test in M3-T002. When git creates a detached-HEAD worktree, it
copies the index of the current branch, which in this case happened to include an
uncommitted working-tree state with these empty files present. They were artefacts of
the development environment's home directory being partially reflected into the repo.

**Decision:** Delete all empty dot-files (`.bashrc`, `.bash_profile`, `.gitconfig`,
`.zshrc`, `.zprofile`, `.bash_logout`, etc.) from the repo root. None were intentional.

**Action:** Files deleted, changes committed and pushed.
