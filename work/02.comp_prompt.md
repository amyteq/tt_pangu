## Mission

Consolidate the long tracking context for Kaggle competition `<competition_slug>` into the structured repository documentation under:

```text
competitions/<competition_slug>/
````

This task turns long issue discussions, worklogs, wiki notes, old work documents, notebook/kernel run notes, submission/LB records, bug lists, and important Chinese notes into compact, English, canonical competition docs.

The original tracking issue remains open for historical reference, but future updates should happen under `competitions/<competition_slug>/`.

## GitHub issue access

Use `gh` read-only commands if available:

```bash
gh issue view <issue_number> --comments --json number,title,state,author,body,comments,labels,url,createdAt,updatedAt
```

Do not edit, close, relabel, assign, or milestone the issue during consolidation.

At the end only, after docs are updated, you may post exactly one cross-reference comment to the tracking issue, if `gh` is available and authenticated.

The comment must:

* link to `competitions/<competition_slug>/README.md`;
* link to the consolidation postmortem;
* say the issue is left open for historical context;
* say future updates will be tracked in `competitions/<competition_slug>/`;
* not close the issue;
* not ask Claude to keep updating the issue.

If `gh` is unavailable, prepare the exact issue comment body in the final report for the human to post.

## Language policy

Canonical competition docs should be English.

Translate Chinese content from:

* issue body;
* issue comments;
* worklogs;
* old `work/` docs;
* wiki notes;
* old README/strategy/task docs;
* any important tracking tables.

When translating:

* keep technical names, code paths, commands, Kaggle slugs, notebook/kernel IDs, metric names, model names, config keys, branch names, issue numbers, PR numbers, and labels unchanged;
* translate human explanations and table headers/cells into English;
* preserve uncertainty explicitly;
* do not invent missing scores, versions, submissions, or decisions.

For important Chinese source documents:

* if the original file is inside the competition directory and will be rewritten in English, first preserve the Chinese original as an adjacent `*_zh.md` file;
* if the original file is outside the competition directory, do not rewrite the original; instead, link it from `references.md` and optionally copy the relevant preserved Chinese excerpt/table into an adjacent `*_zh.md` file under the competition directory;
* `_zh.md` files are historical/source sidecars, not canonical status docs.

Recommended sidecars when useful:

```text
competitions/<competition_slug>/tracking_zh.md
competitions/<competition_slug>/strategy_zh.md
competitions/<competition_slug>/notes_zh.md
```

## Tracking table policy

The original long tracking issue may contain several important tracking tables.

Preserve them in a dedicated file:

```text
competitions/<competition_slug>/tracking.md
```

If the original tables are Chinese or mixed Chinese/English:

* create English canonical tables in `tracking.md`;
* preserve original Chinese tables, if useful, in `tracking_zh.md`;
* keep the same logical rows and columns where possible;
* add a `Current status` column when status can be refreshed;
* add an `Evidence` column linking to issue comments, local docs, run artifacts, or Kaggle kernel/submission records;
* mark unknown data as `unknown`, not blank guesses.

Tracking tables should cover, when source evidence exists:

* notebook/kernel versions;
* code versions;
* experiments;
* ideas / hypotheses;
* push status;
* submit status;
* public LB score;
* private LB score if known;
* Kaggle kernel status;
* blockers;
* bugs;
* next action.

Do not split these legacy tracking tables across many files unless each table clearly maps to a canonical file. Even then, preserve a consolidated view in `tracking.md`.

## Process

1. Run `git status --short`.

   * If there are unrelated uncommitted changes, stop and report them.
2. Inventory source context:

   * target competition directory;
   * tracking issue body/comments;
   * configured source paths;
   * configured source globs;
   * worklogs/wiki/work files;
   * local run registries/artifacts if present;
   * Kaggle read-only status if needed and available.
3. Extract:

   * rules/facts;
   * current status;
   * original tracking tables;
   * ideas and hypotheses;
   * experiments and progress;
   * push/submit/LB history;
   * bugs;
   * references;
   * insights.
4. Translate Chinese content to English canonical docs.
5. Preserve important Chinese originals as `_zh.md` sidecars where useful.
6. Deduplicate repeated ideas and mark superseded decisions.
7. Update competition docs under `competitions/<competition_slug>/`.
8. Update `competitions/README.md` row for this competition.
9. Optionally update `_shared` docs only with clearly cross-competition insights or migration notes.
10. Create the consolidation postmortem.
11. Search for stale references to the old issue tracking flow if relevant.
12. Post exactly one cross-reference comment to the tracking issue, or prepare it if `gh` is unavailable.
13. Run validation commands.
14. Final report.

## Validation commands

Run lightweight validation only:

```bash
git status --short
git diff --stat
git diff --name-status
find competitions/<competition_slug> -maxdepth 4 -type f | sort
```

Search for old tracking references to the issue and source paths:

```bash
grep -R "<tracking_issue>\|<competition_slug>" -n competitions docs README.md PROJECT_STATE.md 2>/dev/null || true
```

If a lightweight markdown lint command already exists in the repo, run it. Otherwise state that no docs-only lint command was found.

Do not run full pytest, UI tests, DB tests, notebooks, model training, Kaggle submit, or Kaggle push for this docs-only consolidation.

## Acceptance criteria

This task is complete when all are true:

* `competitions/<competition_slug>/competition.yaml` is updated.
* `competitions/<competition_slug>/README.md` gives a compact current English status.
* `rules.md` contains competition facts with evidence and uncertainty marked.
* `strategy.md` contains current direction, open discussions, decisions, hypotheses, and rejected ideas.
* `tasks.md` contains current TODOs and progress state.

* `tracking_zh.md` or other `*_zh.md` sidecars preserve important original Chinese tables/docs where useful.
* `submissions.md` contains every known push/submit/LB/kernel-status record found.
* `bugs.md` contains known bugs with status.
* `references.md` contains all important links and source docs.
* `insights.md` contains competition-specific and reusable insight candidates with evidence/confidence.

* No KCA core, `.kca/skills`, tools, migrations, CI, product code, or competition implementation code is modified.
