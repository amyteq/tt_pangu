# M9.3-T001: `design-archaeology` skill — pre-implementation legacy analysis

## Milestone
M9.3: memory-promotion + design-archaeology skills (replaces M9.1 broader hardening plan; see `docs/milestones/m9_3/loop-prompts.md`).

## Goal
Ship a new project skill `.claude/skills/design-archaeology/SKILL.md` that
forces the agent, before any legacy-migration / rewrite / take-over task,
to produce a structured 10-section archaeology report (workflows, hidden
assumptions, accounts/owners, state files, config dimensions, side
effects, preserve/change/drop matrix, open questions, parity test sketch,
evidence). Read-only on the legacy artifact tree; blocks code changes
until the report exists and the human acknowledges §8.

This task ships the skill file only. The first real archaeology report
(against `tools/legacy/kkr.py` + `kkr.yaml`) is produced in M9.3-T003.

## Scope

1. Create directory `.claude/skills/design-archaeology/` and write
   `SKILL.md` with YAML frontmatter:
   - `name: design-archaeology`
   - `description:` (matches `docs/milestones/m9_3/loop-prompts.md` skill brief —
     "Use before implementing any migration, rewrite, or take-over of
     legacy scripts / configs. Produces a structured 10-section
     archaeology report with file:line citations and explicit open
     questions; read-only; blocks code changes until report exists.")
   - trigger keywords visible in the description: `legacy`, `migration`,
     `take over`, `archaeology`, `rewrite`, `port`.
2. Body must define the 10 required output sections **in order** with
   short guidance under each heading (1–3 sentences max each):
   1. Workflows supported (subcommands / entry points)
   2. Hidden assumptions (env, paths, accounts, side effects)
   3. User personas / accounts / owners
   4. State files / registries / caches
   5. Config dimensions (with example values found in tree)
   6. Side effects (network, FS, external APIs)
   7. Preserve / change / drop matrix
   8. Open design questions for human
   9. Behavior parity test sketch (test names, no code)
   10. Evidence — `file:line` citations for every claim
3. Hard rules section ("Must / Must not"), ≥ 5 items, including:
   - Read-only on the legacy artifact tree.
   - Every claim in §1–§7 cites at least one `file:line`.
   - §8 must contain ≥ 1 question even if the agent feels confident.
   - May not write code outside `docs/archaeology/<artifact>.md` until
     report exists and §8 is acknowledged.
   - Output goes to `docs/archaeology/<short-name>.md` — never edit
     the legacy tree.
4. Worked-example pointer: one short paragraph at the bottom of
   `SKILL.md` saying "Canonical worked example: `docs/archaeology/kkr.md`
   (produced in M9.3-T003) — see it for the expected level of detail
   on multi-owner / multi-account assumptions in legacy CLI tools."
5. Do not produce the worked-example report itself in this task — that
   is T003's job.

## Acceptance criteria

1. `.claude/skills/design-archaeology/SKILL.md` exists.
2. YAML frontmatter parses with `python -c "import yaml,pathlib;
   yaml.safe_load(pathlib.Path('.claude/skills/design-archaeology/SKILL.md').read_text().split('---')[1])"`
   and contains `name: design-archaeology` and a non-empty `description`.
3. The body contains all 10 numbered section headings (`grep -c
   "^## [0-9]" .claude/skills/design-archaeology/SKILL.md` ≥ 10).
4. A "Must / Must not" block contains ≥ 5 distinct rules.
5. A worked-example pointer references `docs/archaeology/kkr.md`.
6. SKILL.md body ≤ 200 lines (keep concise; cross-link rather than
   duplicate rules from `inventory-drift-audit` or `research-brief`).
7. `git diff --stat` shows changes ONLY under
   `.claude/skills/design-archaeology/`.
8. Baseline checks still green: `ruff check .`, `ruff format --check .`,
   and `python -m pytest tests/ -x -q` (no behavior change expected).
