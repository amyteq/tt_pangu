## What landed

### M9.2-T000 — Skill scaffold + script implementation

- `.claude/skills/save-log/SKILL.md` — full meeting-notes §2
  frontmatter (`disable-model-invocation: true`, `allowed-tools:
  Bash(python scripts/save_claude_session_log.py*)`,
  `argument-hint: "<name|id>"`, tags `logging`/`handoff`/`claude-code`)
  + a body documenting usage, output shape, safety rules, and
  out-of-scope follow-ups.
- `scripts/save_claude_session_log.py` — 16053 bytes, `chmod +x`.
  Implements selector matching (exact / prefix / substring scoring
  across `job_id` / `session_id` / `name`; ambiguous fuzzy matches
  raise), terminal-state gate (`TERMINAL_STATUSES = {completed,
  complete, stopped, stop}` with `done|success|succeeded` → `completed`
  and `cancelled|canceled` → `stopped` normalisation), transcript
  locator (state.json-embedded path → `<config_dir>/projects/**/<session_id>.jsonl`
  → `<config_dir>/projects/**/*<job_id>*.jsonl`), `uvx
  claude-code-log@latest --detail low --format md --compact` wrapper
  with seven attempt variants (`-o` / `--output` / stdout × `md` /
  `markdown`), nine-pattern secret-scan with the 10th generic
  `(password|passwd|secret|token)` assignment line, and atomic
  overwrite (`.tmp.md` → `replace`).
- `logs/.gitkeep` — zero-byte placeholder.
- `.gitignore` carve-out — `!logs/` + `!logs/**` after the
  existing `**/logs/*` rule, so `logs/` stays trackable while
  every other `logs/` path (e.g. `runs/<comp>/logs/`) stays ignored.
- Read-list discipline: the script reads only `~/.claude/projects/`,
  `~/.claude/jobs/`, and the stdout of `claude agents --json`. It does
  **not** read `.env*`, `~/.kaggle/kaggle.json`, `~/.ssh/**`,
  `~/.aws/**`, `~/.config/gcloud/**`, `~/.config/gh/**`, or
  `secrets/**` — stricter than the CLAUDE.md dev-phase carve-out, on
  purpose (no need for credentials).

## Decision: logs/M9.md (smoke evidence)

Per the M9.2-T001 task spec, the smoke export is evidence — the
reviewer decides per-export whether to commit it. **Decision: keep it
local; do not include in the M9.2 PR.** Rationale: the file is 103 KB
of M9's actual conversation transcript, which already has its own
artifact trail (`docs/milestones/m9/final-review.md`, `docs/milestones/m9/handoff.md`).
Committing it would inflate the M9.2 PR with M9-belonging content and
set a precedent that smoke evidence lives in `logs/` permanently.
The `/save-log` skill's value is producing the file on demand, not
pre-shipping any particular transcript. The header block in any future
manual export is self-contained evidence that the skill works.

The `.gitkeep` placeholder lands so the directory exists in the repo
the first time a future operator runs `/save-log`.

## What's NOT in M9.2 (by design)

- No new schema / migration / Supabase row.
- No CI coverage (the skill is operator-local; `uvx` is a dev
  dependency, not a CI dependency).
- No `claude logs` ANSI-strip fallback. The script fails loudly if the
  transcript JSONL can't be located (with the exact `find` hint).
- No `.claude/commands/save-log.md` mirror. Skills override commands
  of the same name.
- No model-invokable variant. `disable-model-invocation: true` is
  load-bearing.

## Risks / known limitations

- **Frontmatter compatibility.** `argument-hint`, `arguments`,
  `allowed-tools`, `disable-model-invocation`, `tags` are advisory in
  the current Claude Code loader version. The loader did not reject
  the file. If a future loader update tightens schema, the load-bearing
  pair remains `name:` + `description:`; the rest can be trimmed.
- **`uvx` availability.** The skill assumes `uvx` is on `PATH`. The
  Arch dev box has `uvx 0.11.14`; CI runners do not, but no CI job
  exercises the skill.
- **`~/.claude/projects/` layout drift.** Locator falls through three
  paths; if Claude Code reorganises the directory in a future release,
  the locator may miss. Documented in the script docstring.
- **Secret-pattern false positives.** Ten patterns are conservative.
  Any real false positive on a legitimate transcript is closed with
  `--allow-secret-like` after human inspection; the patterns are the
  safety net, not the policy.
- **`CLAUDE_CONFIG_DIR` on this dev box.** Resolved to
  `~/.claude-ayla` (the harness home) at smoke-test time, not
  `~/.claude`. Either works because the script honours
  `CLAUDE_CONFIG_DIR` and falls through to state.json-embedded paths.
  Other dev environments may need to set `CLAUDE_CONFIG_DIR`
  explicitly.
