## 关于你说的两个 Code Agent 概念

我的建议是：**必须区分，而且最好以后固定命名。**

我建议用这两个术语：

| 概念                                                 | 建议名称                                   | 含义                                           | 主要语言/技术                                                   |
| -------------------------------------------------- | -------------------------------------- | -------------------------------------------- | --------------------------------------------------------- |
| 现在帮你开发平台的 Claude Code / ChatGPT / Cursor / Lovable | **Platform-development coding agents** | 外部 AI 工具，用来开发 `kaggle-code-agent` 这个产品本身     | 产品平台以 TypeScript 为主，局部 Python                             |
| 平台以后启动来帮 human user 参加比赛的 agent                    | **Runtime competition code agents**    | 产品内部的比赛执行 agent，用来 research、写代码、跑实验、提交前准备、总结 | Kaggle 以 Python/notebook 为主；核心 worker 先用 Claude Agent SDK |

这个区分会影响很多设计决策：

1. **memory 不同**：Platform-development agents 的共同 memory 是 GitHub repo 文件；Runtime competition agents 的 memory 是平台数据库、run artifacts、competition workspace、conversation/event logs。

2. **安全边界不同**：Claude Code 帮你开发 repo 时不应该读 secrets 或乱 push；Runtime competition agent 还要额外受 Kaggle/CTF/hackathon policy、submission limit、approval gate、sandbox 限制。

3. **技术栈不同**：平台产品本体可以 TypeScript-first；Kaggle runtime worker 应该 Python/notebook-first。

4. **评估方式不同**：平台开发看 CI、PR、unit tests；比赛 agent 看 CV score、leaderboard strategy、experiment reproducibility、submission artifact correctness。

5. **模型路由不同**：开发平台时 Claude Code/ChatGPT/Cursor/Lovable 是工具；runtime 时 Claude Agent SDK + model router 是产品内部能力。

所以我在 `M0-T001-project-baseline.md` 里把这件事设成了 M0 的 acceptance criteria：项目文档必须明确区分这两个 agent 概念。
