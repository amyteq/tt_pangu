## 1. M4 loop execution

**Background:** M4 loop prompts were executed sequentially in this session.
All 11 prompts (T000–T010) finished without manual fix-ups beyond the ones
listed below.

**Notable fixes during the M4 run:**

- `pip install -e .` hit the sandbox read-only filesystem on the first try
  for `~/.local/lib/...` — retried with the disable-sandbox path. This is
  the standard pattern for any command that legitimately needs to write to
  the user's Python prefix.
- `tools/__init__.py` and `tools/kca/__init__.py` were missing, so the
  editable install couldn't discover the `tools.kca` package. Added empty
  files.
- The Python `kca run init` / `record-metric` / `list` commands were
  rewritten to be **FS-first**: they now succeed even when
  `SUPABASE_DB_URL` is unset, and DB write failures degrade to a warning
  instead of a hard exit. The M2 test that asserted "DB unreachable → exit
  non-zero, no FS state" was renamed to `test_db_unreachable_degrades_gracefully`
  and updated for the new contract.
- `metrics.json` is now flat `{key: value}` per M4 spec (Prompt 4).
  Two M2 tests that asserted the old nested `{"value": …, "recorded_at": …}`
  shape were updated.
- DB column name collisions between M1 `experiments` (project_id+name) and
  M4 `experiments` (competition_id+hypothesis+job_id+branch) forced
  migration 0004 to be rewritten as additive `ALTER TABLE … ADD COLUMN IF
  NOT EXISTS`. `db.create_experiment` (M4) was extended to also populate
  the legacy `project_id` + `name` NOT NULL columns so both schema shapes
  coexist on the same row.
- `db.py` symbol collisions (`create_experiment`, `record_metric`,
  `list_runs`) between M2 and M4 were resolved by renaming the M2 versions
  to `*_m2` and updating `tools/kca/run.py` to use the M2 names. `__all__`
  exports both layers.

**Result:** TC-1 Titanic loop completed with `cv_accuracy = 0.7912`,
419-row `submission.csv`, zero pending decisions. No real Kaggle API
calls.

**Browser/research design notes:**

- All fetched content is **untrusted data** per CLAUDE.md operating
  principles. The fetcher returns a dict; the caller is responsible for
  labelling and not passing instructions-as-data into the model.
- Private-net guard (refuses localhost / RFC1918 / link-local / file://) is
  enforced at the `fetch_page` boundary, not at the CLI layer, so library
  callers also can't bypass it.
- Domain allowlist via `KCA_RESEARCH_ALLOW_DOMAINS` is opt-in. When
  unset, all public hosts are allowed and the `external_fetch` gate
  defaults to False (allow) per ADR-0006 minimal-friction principle.
- The Playwright path stays opt-in to keep the default install small
  (~30 MB vs. ~300 MB for chromium).

## DSN note for the M5 run

The user provided `SUPABASE_DB_URL=postgresql://postgres:s3cr3t@supabase-db:5432/postgres`
for M5 validation. `supabase-db` resolves only inside the Docker network,
so the M5 loop should support either:

- Running validation inside a sibling container on the same Docker network
  (the documented `supabase-db` host works there), **or**
- Mapping to the host equivalent `postgres://postgres:postgres@127.0.0.1:54322/postgres`
  for local `pytest` runs from outside Docker.

`docs/milestones/m5/loop-prompts.md` documents both forms in the "Running on Arch
Linux" section.
