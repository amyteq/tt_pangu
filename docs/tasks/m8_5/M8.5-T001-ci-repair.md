## Current known failures (from CI logs)

1. **no-db pytest** fails because:
   - `ModuleNotFoundError: No module named 'nbformat'` — legacy
     `nb2py` / `py2nb` wrappers + roundtrip tests.
   - `ModuleNotFoundError: No module named 'yaml'` — skill loader and
     related tests.
   - `requests is not installed` — `research_fetch` local-server tests.
   - `kca: error: argument group: invalid choice: 'skill'` — the
     `kca skill` subcommand is not registered in the CLI / command
     registry.
   - no-db summary: `18 failed, 61 passed, 10 skipped`.
2. **live-db pytest** fails with the same root causes; summary:
   `18 failed, 71 passed`.
3. **UI job** fails at `pnpm -C ui install --frozen-lockfile` with
   `ERROR packages field missing or empty` — usually means the root
   `pnpm-workspace.yaml` exists but its `packages:` list is empty or
   missing, or the workspace config does not match the `ui/` subproject.

- Prefer adding missing declared dependencies over skipping tests:
  - `PyYAML` (or equivalent) for `import yaml`.
  - `nbformat` for legacy `py2nb` / `nb2py` wrappers.
  - `requests` for `research_fetch` tests, unless the code already
    intends to use `urllib` / `httpx`.
- Ensure `kca skill` is registered in both:
  - CLI argparse / subcommand layer;
  - command registry expected by tests.
- For `pnpm`:
  - inspect root `pnpm-workspace.yaml`;
  - ensure it has a valid `packages:` list, e.g.:
    ```yaml
    packages:
      - "ui"
    ```
  - do not delete the lockfile unless necessary; regenerate only if
    required and explain why.
