# Task: Reorganize docs milestone, handoff, prompt, and task structure

## Mission

Do docs-only housekeeping under `docs/` so milestone files, handoff files, prompt files, and task specs are organized by milestone and easy for Claude Code agents to navigate.

This task is a documentation migration/refactor only.

Do not implement product features.  
Do not modify KCA core code.  
Do not modify runtime competition code.  
Do not modify permission settings or hooks.  
Do not run Kaggle commands.  
Do not create a PR, push, or merge unless explicitly approved later.

## Read first

Read these files before making changes:

- `CLAUDE.md`
- `README.md`
- `PROJECT_STATE.md` if present
- `docs/milestones.md` if present
- `docs/handoff-prompt.md` if present
- `docs/engineering-practice.md` if present

Also inventory these directories if present:

- `docs/`
- `docs/handoffs/`
- `docs/prompts/`
- `docs/tasks/`
- `.claude/agents/`
- `.claude/commands/`
- `.claude/skills/`

## Context

The current milestone protocol may still reference:

- `docs/milestones.md`
- `docs/handoffs/m{x}-handoff.md`
- `docs/handoff-prompt.md`
- milestone task files directly under `docs/tasks/`

The desired direction is to consolidate milestone-related material under `docs/milestones/`, and organize `docs/tasks/` by milestone.

Important:
- Preserve useful history.
- Prefer `git mv` for file moves.
- Do not silently delete content.
- If a file is obsolete, explain why before deleting it.
- If a file is ambiguous, do not move/delete it; record the uncertainty in the migration report.

## Desired migration decisions

### 1. Move milestone files to `docs/milestones/`

Move all milestone-related docs currently under `docs/` into `docs/milestones/`.

Examples of files to classify as milestone-related:

* `docs/milestones.md`
* `docs/m0-final-review.md`
* `docs/m1-final-review.md`
* `docs/m2-final-review.md`
* `docs/m3-final-review.md`
* `docs/m4-final-review.md`
* `docs/m5-final-review.md`
* `docs/m6-final-review.md`
* `docs/m7-final-review.md`
* `docs/m8-final-review.md`
* any `mX-*` milestone review, final review, closeout, validation, or handoff docs

Preferred mapping:

```text
docs/milestones.md
  -> docs/milestones/README.md

docs/mX-final-review.md
  -> docs/milestones/mX/final-review.md

docs/mX-*.md
  -> docs/milestones/mX/<normalized-name>.md
```

If `docs/milestones.md` is widely referenced, still move the canonical content to `docs/milestones/README.md`. A short compatibility stub at `docs/milestones.md` is allowed only if useful, but it must be less than 10 lines and all internal repo references should prefer the new path.

### 2. Move handoff files into `docs/milestones/`

Move per-milestone handoff files from:

```text
docs/handoffs/mX-handoff.md
```

to:

```text
docs/milestones/mX/handoff.md
```

Move the generic handoff template from:

```text
docs/handoff-prompt.md
```

to:

```text
docs/milestones/_templates/handoff-prompt.md
```

only if it exists and clearly acts as the generic milestone handoff template.

After moving, update the milestone final-review protocol so it says:

```text
Per-milestone handoffs live under docs/milestones/mX/handoff.md.
The generic handoff template lives under docs/milestones/_templates/handoff-prompt.md.
```

If any old `docs/handoffs/` directory remains empty after safe moves, remove the empty directory. Do not delete non-empty directories with ambiguous content.

### 3. Review `prompts/M1-loop-prompts.md`

Check both possible locations:

```text
prompts/M1-loop-prompts.md
docs/prompts/M1-loop-prompts.md
```

If the file exists:

1. Read it.
2. Decide whether it is still relevant.
3. If relevant to M1, move or merge it into:

```text
docs/milestones/m1/loop-prompts.md
```

or, if it is better treated as historical notes:

```text
docs/milestones/m1/notes.md
```

4. If it is obsolete and fully duplicated elsewhere, delete it only after recording the reason in:

```text
docs/milestones/m1/README.md
```

and in the migration report.

Do not delete it merely because the file is old. Delete only if:

* its content is superseded;
* its useful content has been merged elsewhere; or
* it is clearly irrelevant to the current project.

If uncertain, move it to:

```text
docs/prompts/archive/M1-loop-prompts.md
```

and record the uncertainty.

### 4. Reorganize `docs/tasks/` by milestone

Move task files under `docs/tasks/` into milestone-specific folders.

Preferred mapping:

```text
docs/tasks/M0-T001-project-baseline.md
  -> docs/tasks/m0/M0-T001-project-baseline.md

docs/tasks/M1-*.md
  -> docs/tasks/m1/

docs/tasks/M2-*.md
  -> docs/tasks/m2/

...
```

For task files that do not match `M<number>`:

* If clearly housekeeping-related, move to `docs/tasks/housekeeping/`.
* If competition-tracking-related, keep or move under `docs/tasks/competition-tracking/`.
* If current backlog but not milestone-specific, move to `docs/tasks/backlog/`.
* If unclear, move to `docs/tasks/uncategorized/` and record why in `docs/tasks/README.md`.

Create or update:

```text
docs/tasks/README.md
```

It should include:

* purpose of `docs/tasks/`
* folder convention
* how to execute a task file with `/goal Execute task from ...`
* where to put milestone tasks
* where to put housekeeping tasks
* where to put competition-tracking tasks
* how to handle uncategorized tasks

## Process

1. Run `git status --short`.

   * If the working tree already has unrelated changes, stop and report them.
2. Inventory docs:

   * list milestone-related files under `docs/`;
   * list files under `docs/handoffs/`;
   * list files under `docs/prompts/` and `prompts/` if present;
   * list files under `docs/tasks/`;
   * list `.claude` agent/command/skill files that reference moved paths.
3. Propose the move map internally, then perform safe moves with `git mv`.
4. Merge or archive `M1-loop-prompts.md` according to the rules above.
5. Create/update `docs/milestones/README.md`.
6. Create/update per-milestone `README.md` files only where useful.
7. Create/update `docs/tasks/README.md`.
8. Update references across allowed paths.
9. Create `docs/milestones/migration-report.md`.
10. Run validation commands.
11. Summarize results.

## Validation commands

Run lightweight docs validation only:

```bash
git status --short
git diff --stat
git diff --name-status
find docs -maxdepth 5 -type f | sort
```

```bash
grep -R "docs/handoffs\\|docs/handoff-prompt.md\\|docs/milestones.md\\|prompts/M1-loop-prompts.md\\|docs/prompts/M1-loop-prompts.md" \
  -n README.md PROJECT_STATE.md CLAUDE.md AGENTS.md docs .claude 2>/dev/null || true
```

```bash
grep -R "docs/tasks/M[0-9]" \
  -n README.md PROJECT_STATE.md CLAUDE.md AGENTS.md docs .claude 2>/dev/null || true
```

If a Markdown lint command already exists in the repo and is lightweight, run it. Otherwise state that no Markdown lint command was found.

Do not run full pytest, UI tests, DB tests, or CI locally for this docs-only migration unless the repo explicitly has a fast docs-only validation command.

## Acceptance criteria

This task is complete when all are true:

* `docs/milestones/README.md` exists and contains the canonical milestone index or migrated content from `docs/milestones.md`.
* Per-milestone final review files, if present, are under `docs/milestones/mX/`.
* Per-milestone handoff files, if present, are under `docs/milestones/mX/handoff.md`.
* The generic handoff template, if present and moved, is under `docs/milestones/_templates/handoff-prompt.md`.
* `docs/handoffs/` is empty/removed or contains only files that could not be safely classified, with explanation in the migration report.
* `M1-loop-prompts.md`, if present, is either merged, moved, archived, or deleted with a clear reason.
* `docs/tasks/README.md` exists and explains the new task organization.
* Milestone task files are organized under `docs/tasks/mX/` where the milestone is clear.
* Non-milestone task files are organized under `docs/tasks/housekeeping/`, `docs/tasks/competition-tracking/`, `docs/tasks/backlog/`, or `docs/tasks/uncategorized/`.
* References in allowed files are updated to the new paths.
* `.claude/agents/**`, `.claude/commands/**`, and `.claude/skills/**` no longer point at moved old paths, except where deliberately documented.
* `.claude/settings*.json` and `.claude/hooks/**` are unchanged.
* No source code, tests, migrations, workflows, or KCA core files are modified.
* `docs/milestones/migration-report.md` exists and lists old path → new path mappings.
* Validation commands have been run and summarized.

## Stop conditions

Stop and summarize blockers if any of these happens:

* working tree has unrelated uncommitted changes at the start;
* source files are too ambiguous to classify safely;
* moving files would risk data loss;
* many references require changes outside allowed paths;
* a required change would touch `.claude/settings*.json`, `.claude/hooks/**`, `.kca/**`, `tools/**`, `src/**`, `services/**`, `supabase/**`, `ui/**`, tests, or workflows;
* a secret or credential path is encountered;
* a remote side effect would be required;
* the task expands beyond docs housekeeping;
* acceptance criteria are met.
