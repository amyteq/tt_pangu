建议把这个 housekeeping prompt 做成一个**单独的 docs-only task file**，不要混进 competition tracking prompt。这个任务的核心是“文档目录重构 + 引用修复 + 迁移记录”，不应该顺手改 KCA core、权限策略、hooks 或运行长测试。这样符合你项目里“GitHub repo 是 source of truth、任务要有 acceptance criteria / stop condition、用 `/goal` 执行”的规则。 

执行方式：

```bash
claude --bg \
  --name "comp" \
  --permission-mode auto \
  "/goal Execute task from `work/01.hk-001-tasks.md` until its acceptance criteria pass or its stop conditions trigger. Read the task file fully first. Treat the task file as immutable. Do not create modify KCA core unless explicitly approved. Work in a worktree, include local unstaged changes and open a PR on completion."
```

优化后的 task file 内容: [01.hk-001-tasks.md](01.hk-001-tasks.md)

我会把这次 housekeeping 单独开一个 branch，例如：

```bash
git checkout main
git pull --rebase
git checkout -b claude/docs/HK-001-docs-milestone-task-cleanup
````

然后先手动创建上面的 task file，再执行：

```bash
claude --bg \
  --name "HK-001-docs-milestone-task-cleanup" \
  --permission-mode auto \
  "/goal Execute task from docs/tasks/housekeeping/001-docs-milestone-task-structure-cleanup.md until its acceptance criteria pass or its stop conditions trigger. Read the task file fully first. Treat the task file as immutable. Do not create PR, push, or modify KCA core unless explicitly approved."
```

这里我特意让 prompt 允许更新 `.claude/agents/**`、`.claude/commands/**`、`.claude/skills/**`，但禁止动 `.claude/settings*.json` 和 `.claude/hooks/**`。原因是你确实想修正 agent/skill 定义里的文档路径，但权限和 hooks 是安全边界；当前项目规则也强调 secrets、remote side effects、Kaggle submit/kernel push 等都要被保护或人工批准。
