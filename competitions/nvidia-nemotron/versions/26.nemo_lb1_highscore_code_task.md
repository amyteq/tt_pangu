# Implementation objective

Create a single Python file:

`{{ single_file_target }}`

The file should be concise but production-oriented. It should be able to:

1. Read `train.csv`.
2. Classify rows by task category.
3. Generate solver-style SFT traces for every row.
4. Generate optional verified synthetic examples for the hard categories.
5. Train a rank<=32 LoRA adapter if GPU training is later approved.
6. Package a root-level `submission.zip`.
7. Run local smoke / preflight checks.

The implementation should borrow the most important LB1/LB3 ideas:

- solver-generated traces rather than free-form LLM traces;
- 24-rule inventory for equation numeric and cryptarithm;
- prompt-level mode and non-repeated non-join group constraints;
- cryptarithm signature-catalog or pattern-catalog memory traces;
- DFS-style consistency checking narration for cryptarithm;
- bit manipulation column-wise solving;
- HEX compression for long bit columns;
- bit rule families including shifts, rotations, NOT, XOR, AND, OR, majority, parity, choice / conditional families, and selected 3-input compositions;
- bit repair: selected 8-rule sequence should be projected to nearby valid catalog sequences, then verified against examples;
- exact `\boxed{}` final answer format;
- binary leading zeros;
- exact strings/symbols;
- two-stage or staged training hooks if feasible: memorization drills first, execution traces second;
- response-only loss masking;
- LoRA rank 32 / alpha 32;
- seq length aligned with official `max_tokens=7680` as much as practical;
- timeout-safe save and zip behavior.

The single file does not need to reproduce the full 1st-place training volume, but it should expose CLI flags so we can scale data and training later.

# Suggested CLI for the new file

The file should support commands similar to:

```bash
python {{ single_file_target }} build-corpus \
  --train-csv <path> \
  --out {{ version_dir }}/corpus.jsonl \
  --synthetic-bit 1000 \
  --synthetic-equation 1000 \
  --synthetic-cryptarithm 1000 \
  --seed 42

python {{ single_file_target }} smoke \
  --train-csv <path> \
  --out-dir {{ version_dir }}/smoke

python {{ single_file_target }} train \
  --corpus {{ version_dir }}/corpus.jsonl \
  --base-model {{ base_model }} \
  --adapter-out {{ version_dir }}/adapter \
  --rank 32 \
  --alpha 32 \
  --seq-len 4096 \
  --lr 2e-4 \
  --epochs 1

python {{ single_file_target }} package \
  --adapter-dir {{ version_dir }}/adapter \
  --zip-out {{ version_dir }}/submission.zip

python {{ single_file_target }} preflight \
  --zip {{ version_dir }}/submission.zip
```

It is acceptable to use a simpler CLI if it is well documented and covers the same functions.

# Code quality requirements

The Python file should be readable and self-contained. Prefer:

- pure-Python solvers/generators for CPU stages;
- lazy imports for heavy packages such as torch, transformers, peft, bitsandbytes;
- clear category-specific functions;
- deterministic RNG seeds;
- explicit `source` and `category` fields in JSONL records;
- comments marking which parts are LB1-derived, LB3-derived, or our additions;
- no hidden network calls;
- no hard-coded secrets;
- no absolute local-only paths except via CLI args or config.
