## 一、这是什么比赛

**ARC-AGI（Abstraction and Reasoning Corpus，抽象与推理语料）** 是 François Chollet（Keras 作者）2019 年
提出的智能基准。它的核心信念是：**真正的智能 = 在训练分布之外高效习得新技能的能力**，而不是把见过的东西背下来。

每道题（task）给你 **2–5 对**「输入网格 → 输出网格」的示范（demonstration pairs），让你**自己推断出隐藏的
变换规则**，再把规则套用到 1–3 个**新的测试输入**上，画出正确的输出网格。每个网格是 **1×1 到 30×30** 的方阵，
格子取值 **0–9**（代表 10 种颜色，颜色含义每题自定、跨题无意义）。因为每道题的规则都是独一无二、训练中没见过的，
**死记硬背没用** —— 这正是它测「智能」而非「记忆」的设计。

**ARC-AGI-2**（2025 年 5 月论文 arXiv:2505.11831）是第二代，专门针对「第一代被攻破的方式」做了加固：

- **第一代（ARC-AGI-1）** 最终被「规模 + 测试时训练」攻破：2024 年 Kaggle 冠军 ARChitects 用 TTT 拿到私榜
  **53.5%**。本质上变成了工程/算力问题。
- **第二代（ARC-AGI-2）** 做了三件事：
  1. **删掉所有能被暴力搜索/枚举碰运气解出的题**；
  2. 加入更难的推理类型：**符号解释、组合式多规则、上下文调制、顺序依赖**（下文「四类新难点」详述）；
  3. 把**算力效率（每题成本）当作一等评分约束**。
- 结果极其悬殊：同一个 o3-medium，在 ARC-AGI-1 上约 53%，到 ARC-AGI-2 **掉到约 3%**；而人类个人平均仍有
  **66%**，校准组（panel）能解 **100%**。这个「人类轻松、AI 几乎做不出」的巨大落差，就是这个比赛的意义。

主办方是 **ARC Prize 基金会**（Mike Knoop + François Chollet），比赛跑在 Kaggle 上。

## 四、评测方式

- **指标：pass@2，逐测试输入取精确匹配，再对全私榜取均值。**
  - 每个测试输入，提交**恰好 2 个候选输出网格**；只要**有一个**和标准答案**逐像素完全一致**（形状 + 每个格子
    都对），该输入记 1 分，否则 0 分。
  - 最终分 = 所有测试输入得分的平均。
- **三套隐藏集**：公开训练 1000 题（不计分，用来练）；公开评测 120 题（本地验证用）；**半私榜 120 题（驱动 Kaggle
  实时排行榜）**；**私榜 120 题（最终发奖）**。半私榜与私榜被刻意校准成同分布（IID），所以**线上分应能大致反映私榜分**。
- **人类基准**：公开评测个人平均 66%、校准组 100%；人类解出一题中位耗时约 2.2 分钟。

## 五、数据格式

每题一个 JSON：

```json
{
  "train": [ {"input": [[...]], "output": [[...]]}, ... ],   // 2–5 对示范（通常 ~3 对）
  "test":  [ {"input": [[...]]}, ... ]                        // 1–3 个测试输入（答案隐藏）
}
```

- 网格 = 整数二维数组，值 0–9（颜色），尺寸 1×1 … 30×30。
- 公开训练集 1000 题里**混入了一部分 ARC-AGI-1 的旧题** + 新题；⚠ 新题确切数量官方未明说。
- 训练集难度分布故意更宽，评测/私榜则被紧密校准。

## 七、前人怎么拿分（SOTA 与方法谱系）

### 2024（ARC-AGI-1）冠军 ARChitects — 53.5%
- **测试时训练 TTT（Test-Time Training）**：推理时拿**这一道题的示范对**做数据增强、临时微调一个预训练 LLM，
  再用微调后的模型出答案。**最大的杠杆**。
- **数据增强**：旋转/翻转/转置/颜色置换，把几对示范扩成训练集；预测时再**逆变换回去做投票**。
- **合成数据（re-arc）** 预训练打底 + 多 checkpoint 集成 + 针对 pass@2 的**双候选选择**。

### 2025（ARC-AGI-2 首届）Kaggle 终榜
| 名次 | 队伍 | 私榜 | 每题成本 | 核心方法 |
|---|---|---:|---|---|
| 1 | **NVARC**（NVIDIA GM 队）| **24.03%** | ~$0.20 | TTT 框架 + Tiny Recursive Model(TRM) + 大量合成数据，~4B 模型 + 测试时自适应 |
| 2 | ARChitects | 16.53% | — | 2D 感知的**掩码扩散** LLM + 递归自我精修 + 视角打分 |
| 3 | MindsAI | 12.64% | — | 重工程化 TTT：测试时微调 + 增强集成 + tokenizer dropout |

**结论：NVARC 的 24% 是 2025 年 Kaggle 约束下的「地板」。** 当年 1455 队参赛，85% 的 Bonus 门槛无人达到。

### 方法谱系与「赛内可行性」
| 方法 | 思路 | 赛内适配 |
|---|---|---|
| **测试时训练 TTT** | 用单题示范临时微调 | ★★★ 已验证的 Kaggle 赢法，可离线在 L4x4 跑 |
| **程序合成 / DSL 搜索** | 在网格变换 DSL 里搜一个符合所有示范的程序 | ★★ ARC-2 组合爆炸，需强先验剪枝 |
| **神经引导搜索** | LLM 提议程序/编辑，验证器对照示范检查 | ★★ 2025 的「精修循环」主题，须离线 + 预算内 |
| **递归/迭代精修** | 模型反复用「与示范的拟合度」反馈来改候选 | ★★★ 2025 主流范式（NVARC TRM、ARChitects 扩散精修）|
| **纯前沿 LLM prompting** | 调 API | ✗ 赛内关闭联网 |

> ARC Prize 官方 2025 复盘的金句：**「准确率现在主要卡在工程，效率卡在科学/想法。」** 所有顶尖方案本质都是
> 某种**精修循环**：生成候选 → 用示范打分 → 变异/重训 → 重复；区别只在候选是「自然语言描述 / 显式代码 / 模型权重(TTT)」。

## 八、我看到的核心挑战

1. **四类新难点（ARC-AGI-2 论文专门设计来打败现有方法）**
   - **符号解释（Symbolic interpretation）**：符号的含义在每题上下文里临时定义，得做「角色赋值」，不能只靠颜色/空间套路。
   - **组合式多规则（Compositional）**：多个规则**同时且相互影响**地作用，一个规则的输出会改变另一个的作用域 ——
     单规则程序合成在这里崩。
   - **上下文调制（Contextual modulation）**：同一个视觉元素在不同上下文下触发不同变换，靠「模式 → 规则」死映射会错。
   - **顺序依赖（Sequential dependency）**：「不先执行前 N 步就无法预测第 N+1 步」，堵死了走捷径的推断，要求维护计算状态。

2. **效率是硬约束，不是加分项**：12 小时 / 无联网 / $10K（≈$83/题）。这直接**枪毙暴力搜索和巨型集成**，逼你
   用小模型 + TTT + 聪明的搜索剪枝。

3. **反记忆设计**：题型刻意不出现在大模型预训练语料里；训练集分布宽、私榜窄校准，过拟合训练分布会被惩罚。

4. **本地评测与线上的对齐风险**（来自 nemo 的教训）：必须先建**本地 pass@2 评测**并用已知公开 notebook 分校准，
   否则会在看不见的榜上盲目迭代、CV/LB 背离。

5. **两条领奖路线要想清楚**：85% Bonus 今年大概率拿不到；进步奖比分数；**大奖比 writeup 且保证发放** —— 别只顾刷分。

## 九、可以提分的技术与技巧（我的 ideas）

按「性价比 × 便宜程度」排序，详见 `strategy.md`（H1–H5 假设）与 `tasks.md`（T0–T4 可执行任务）。

1. **先建本地基础设施（最高优先，零算力）**：数据加载器 + 网格可视化查看器 + **pass@2 精确匹配评分器**，
   并用一个已知公开 notebook 的分数校准它。所有实验都依赖这个能离线打分的环。

2. **复现 TTT 基线（地板 ~24%）**：照 NVARC/ARChitects 谱系，在 ≤4B 的底座上做「单题示范增强 → 临时微调 → 解码」。
   这是后续一切的底座。

3. **为 pass@2 做候选选择/投票（便宜的提分）**：因为有 2 次机会，生成 N≥8 个候选后用**增强一致性投票 / 示范拟合
   度重排**挑出最好的 2 个，比直接取 top-2 往往更高。2024 年这一招很关键。

4. **针对四类新难点的合成数据**：写一个能生成**多规则/上下文调制/顺序依赖**类题目的生成器（re-arc 思路的扩展）
   做预训练，抬高 TTT 在新题型上的天花板。**注意别单一题型过量**（nemo H2 教训：单类过量会稀释其他类）—— 要测
   **每类的增量**而非只看总分。

5. **按题型路由 / 专精**：先判别题属于哪一类（符号/组合/上下文/顺序），再路由到最擅长它的 solver 或 adapter。

6. **神经引导的 DSL 搜索 + 精确验证器**：对「可程序化表达」的子集，让 LLM 提议短程序、用验证器**逐示范精确校验**
   （零假阳性）。只在它能补 TTT 解不出的题时才值得做。

7. **递归精修模型（TRM 风格）**：NVARC 用过的效率前沿架构 —— 小网络反复迭代到不动点，做「分数 vs 成本」曲线找拐点，
   契合 $10K/12h 的效率约束（对大奖 writeup 也是很好的「效率/普适性」叙事）。

**要避免的坑**（`strategy.md` 详列）：不要赌看不见的榜、不要走暴力搜索、不要假设 API 大模型的分能迁移到赛内、
合成数据不要单类过量、坚持「一次只改一个有意义的变量」并完整记录。
