## Scope

1. Create `.claude/skills/memory-promotion/SKILL.md` with YAML
   frontmatter:
   - `name: memory-promotion`
   - `description:` — "Use to distill GitHub issue/PR/review/meeting-notes
     content into proposed patches against canonical memory (PROJECT_STATE,
     ADRs, handoffs, milestones). Propose-only — never edits canonical
     files; writes proposals to `docs/proposals/`. Inherits the
     no-inference-from-ambiguity rule from `github-issue-triage`."
   - trigger keywords visible in the description: `memory`, `promotion`,
     `decision`, `comment`, `proposal`, `handoff`, `ADR`.
2. Body must define the 4-phase workflow **in order**:
   - Phase 1 — Evidence gathering. Inputs: GitHub issue/PR URL or
     number, `docs/meeting-notes/<date>-rN.md` path, or PR review
     thread (via `gh api repos/<owner>/<repo>/pulls/<n>/comments`).
     Quote verbatim; never paraphrase as fact.
   - Phase 2 — Extraction. Required structured output keys:
     `confirmed_requirements`, `changed_requirements`,
     `confirmed_design_decisions`, `changed_design_decisions`,
     `open_questions`, `blockers`, `proposed_labels`. Every entry
     under `confirmed_*` cites source line/URL; ambiguous items go
     to `open_questions`, not `confirmed_*`.
   - Phase 3 — Patch proposal. Writes to
     `docs/proposals/memory-<YYYY-MM-DD>-<short>.md` with: target file
     (must be one of the canonical four), exact diff or "insert after
     section X" instruction, human-approval checkbox
     `[ ] approved by <name> on <YYYY-MM-DD>`, and a link back to
     evidence.
   - Phase 4 — Human gate. Skill MUST stop after Phase 3. A human (or
     a follow-up explicit task) applies the patch. The skill never
     edits the four canonical files itself.
3. Hard rules section ("Must / Must not"), ≥ 6 items:
   - Ambiguous comments → `open_questions`, never `confirmed_*`.
   - Quote source verbatim with anchor (URL+anchor or `file:line`).
   - May not edit `PROJECT_STATE.md`, `docs/adr/**`,
     `docs/milestones/README.md`, `docs/milestones/*/handoff.md`. Only writes to
     `docs/proposals/**`.
   - No `gh` write commands (no `issue/pr edit|comment|close|label`).
     Reading via `gh api` is allowed.
   - Inherits the `github-issue-triage` guardrail: never invent a
     `decision:confirmed` from silence.
   - Does not promote to or from the `memory/` user auto-memory
     directory — that is a separate system (see ADR 0015).
4. Write `docs/adr/0015-memory-promotion-model.md`. Required sections:
   - Status: Accepted (with date 2026-05-26)
   - Context: why we need a propose-only promotion path
   - Decision: the canonical memory file list:
     `PROJECT_STATE.md`, `docs/milestones/README.md`,
     `docs/milestones/m{N}/handoff.md`, `docs/adr/NNNN-*.md`.
   - Consequences: human gate is load-bearing; `docs/proposals/` is
     a staging directory; `memory/` user auto-memory is NOT canonical
     and is out of scope for this ADR.
   - Relationship to existing skills: distinguishes `memory-promotion`
     from `github-issue-triage` (which gates labels + AI pickup) and
     from `inventory-drift-audit` (which scans for contradictions).
5. Write `docs/architecture/memory-promotion.md`. Required content:
   - 1-paragraph problem statement.
   - ASCII data-flow diagram: evidence sources → extraction →
     `docs/proposals/` → human gate → canonical memory.
   - Explicit list of canonical files (mirrors ADR 0015).
   - Cross-link to `.claude/skills/memory-promotion/SKILL.md` and
     `.claude/skills/github-issue-triage/SKILL.md`.
6. Do **not** propose any patch against `PROJECT_STATE.md` or other
   canonical files in this task. T003 produces the first real proposal.
7. Create directory `docs/proposals/` with a `.gitkeep` and a brief
   `docs/proposals/README.md` (≤ 30 lines) describing what lives here
   and the propose-only rule.

   the explicit "may not edit canonical files" rule.

6. `docs/proposals/README.md` exists and describes the propose-only
   rule in ≤ 30 lines; `docs/proposals/.gitkeep` exists.

   `docs/architecture/memory-promotion.md`, `docs/proposals/`.
